# dividi(a, b) Implementation Plan

> **For agentic workers:** con tollgate l'esecuzione è `/tollgate:execute` (agenti `tollgate:implementer` e `tollgate:task-reviewer`).

**Goal:** aggiungere `dividi(a, b)` a `src/calc.py` con il test `test_dividi`.

**Architecture:** funzione pura a una riga, accanto a `somma` e `sottrai`; nessun controllo sugli argomenti.

**Tech Stack:** Python, `unittest` (runner di `tools/unittest_junit.py`).

**Spec:** issue #104 (nessuna spec separata, lavoro L1).

## Fatti verificati

- `src/calc.py` contiene solo `somma(a, b)` e `sottrai(a, b)`, funzioni di una riga, senza controlli.
- `tests/test_calc.py` ha la classe `CalcTest(unittest.TestCase)` con `test_somma` e `test_sottrai`; importa con `from src.calc import somma, sottrai`.
- Il gate esegue `python3 tools/unittest_junit.py` (`tollgate.toml`, `[commands] verify`).

## Decisioni

- `dividi` usa l'operatore `/`: `dividi(6, 3)` dà `2.0`, che è uguale a `2` in `assertEqual`.
- Nessun controllo sullo zero: `ZeroDivisionError` di Python si propaga (richiesto dall'issue).
- Il test va nella classe `CalcTest` esistente, non in una nuova.

## Interfacce

- `dividi(a, b)` in `src/calc.py` → `a / b`.
- `CalcTest.test_dividi` in `tests/test_calc.py`; l'import diventa `from src.calc import dividi, somma, sottrai`.

## Must-have

- M1. `dividi(6, 3)` vale 2 — test: tests.test_calc.CalcTest::test_dividi

## Scope

- `src/calc.py`
- `tests/test_calc.py`

Nessun altro file.

## Punti di arresto

- Se serve toccare un file fuori dallo scope, fermarsi e chiedere.
- Se l'issue dovesse richiedere controlli su `b == 0`, fermarsi: contraddice l'issue.

## Rischi

- `/` restituisce `float`: `assertEqual(2.0, 2)` passa. Se si volesse un `int` servirebbe `//`, ma l'issue non lo chiede.
- La divisione per zero non è testata (l'issue la lascia al comportamento di Python, senza controlli).
